## 1. 现状与直接问题

1. 当前 `/farm-overview` 已有卫星地图、动态村庄分组、右侧抽屉和基础数据概要，但农场 `LZH-ROOT` 的首屏集中显示边界待登记、对象版本、资料来源、建档时间、权限范围等系统元数据。用户难以迅速知道“农场有多少村庄/地块/塘口/设施、有什么要关注、下一步能做什么”。
2. `/farm-overview` 中村庄维护藏在 `RegionManagement` 的折叠区域；现有 `/objects` 的薄 UI 主要面向 `field`、`pond`；`/devices` 页面以列表为主，虽有 `/api/v1/devices` POST 与 `saveDevice()`，并不等于用户已有显眼且完整的新增设备操作路径。
3. 生产库当前缺少可用于演示多村与业务状态的现场对象。不得为了填满页面把合成记录导入正式 `objects`、`devices`、`map_regions`、`alerts` 或 `observations`。
4. D3 仍有真实现场验收限制。这次目标是更好地验证**界面和操作路径**，并非以演示资料替代 T01—T15 的现场验收结论。

### 本次目标

- 用户能在地图工作台**快速找到并真正走通**村庄、地块/塘口、固定设施、机动设备的登记/维护路径，且保持原业务所有权与安全规则。
- 首屏详情突出实际有用的信息，系统记录仍可在折叠区域查看；不同类型有不同概要。
- 即使真实现场数据为空，也能在一个**醒目、可退出、完全隔离的只读演示模式**中体验多村、农田、塘口、设施、无人机和农机的完整地图交互。

## 2. 不变的产品约束

- 保持 **John Deere 式浅色农业运营视觉**、平台原导航、左侧可折叠目录、中央 **OpenLayers + 天地图卫星影像**、右侧默认关闭的覆盖式详情抽屉；手机端目录抽屉/底部详情。
- **全场看分布、放大看设施、点击看概要**；左侧目录解决“在哪里”，图层入口解决“显示什么”。
- 正式业务依旧以 `objects`、`devices`、`data_sources`、`points`、`map_regions`、`machinery_bindings` 等原表和接口为准；农业/设备编辑走**原业务模块**，地图右侧只读概要。
- 不修改、不替代 `/map`、`/map-prototype`、`/terrain`、`/imagery`、`/machinery` 等既有页面或权限判定；不重建告警、工单、水质监测及控制系统。
- 草稿边界、待核实位置、设备登记、终端绑定、真实遥测新鲜度、告警状态之间严格区分。**任何地图 UI 不得发送现场设备控制指令**。
- 有权限用户“查看”和“配置”不同。前端入口之外，服务端仍必须执行原来的角色/对象级授权；专家不能凭地图汇总泄露未授权数据。

## 3. 用户参考图可如何用于演示

用户图片包含围绕梁子湖及水域边缘的多片农业地带，能辨识沙湾村、长岭居委会等地名，以及用不同颜色标识的农田、水域、道路/交通廊道、沟渠与设施符号。**它适合参考空间组成与视觉层次，但不提供我们可以直接可信使用的 WGS84 顶点坐标、正式行政边界或经营权属。**

- 设计灵感：左侧/中部/右侧分散的村落经营片区；水田与塘口相间、渠道和道路穿过；固定灌排设施、移动农机作为农业对象的关联信息。
- 演示分组采用 **“沙湾示范片区”“长岭示范片区”“湖东示范片区”**。前两项借用了图片中可见地名作灵感，但均为**虚构演示经营分组**；第三项完全是虚构分组。它们**不宣称等于行政村范围**，也不代表项目已在这些地方经营。
- 可以为演示图层生成少量合成的 GeoJSON 点、线、面，以相互分散的空间位置表达水田、塘口、水闸和道路关系；它们只属于 `demo` 图层，必须用虚线或半透明样式及“演示区域（非测绘边界）”说明。**不要从图片像素倒推真实坐标，也不要在卫星图上宣称虚构多边形是现场地块。**
- 可使用已有地图初始化视角附近的近似**合成展示锚点**让演示物体分散呈现，但不在文档中给出所谓精确位置；演示位置必须带虚构来源标签，不能与 `device_positions` 或真实空间对象合并。
- 图中道路、水系、标注是**构图参考**，不是本次新增官方路网/土地分类业务。

## 5. 演示模式的隔离与边界（必须先做对）

### 5.1 可见性

- 首页默认 **“真实数据”** 模式；提供明显的“切换至演示”入口。真实库为空时展示真实空状态和“查看演示效果”，**不能悄悄切到模拟数据**。
- 选择演示后出现持续醒目的顶层说明：**“演示模式｜当前所有村庄、地块、设备位置、状态和告警均为合成示例，不代表真实现场。”** 右侧详情与模拟指标旁至少有“演示”语义提示。
- 提供明显“退出演示，返回真实数据”按钮。切换模式时清除/隔离选中对象、搜索、当前位置、计数和暂存地图状态，避免 `sessionStorage` 恢复真实 UUID 到演示页面或反过来。
- 真实数据模式的空值要如实呈现，**网络失败不能自动借用演示数据来掩盖故障**。保留 D3 原有“已加载但尚未重新核实”的离线提示。

### 5.2 实现隔离

- 演示 fixture 仅供前端/明确隔离的演示视图读取；**禁止对** `objects`、`map_regions`、`map_region_links`、`devices`、`data_sources`、`device_positions`、`alerts`、`observations`、`work_orders`、`machinery_bindings` 等正式业务表做任何合成写入。
- 禁止把 `demo:` ID 传给 `/api/v1/*` 真实写接口或生成业务编辑链接；演示模式所有新增、编辑、归档、核实、控制等操作只提供提示或切回真实模式，不允许真的落库。
- `real` 和 `demo` 数据源应在明确类型边界区分，地图对象 ID、区域 ID、聚合数量、业务状态及缓存隔离；不得在同一层合并统计。演示逻辑不放进 `farmOverview()` 正式授权聚合返回里。
- 演示的无人机/农机不宣称已绑定终端；演示时可以展示“演示坐标，非真实定位”以便展示位置图标，**不得显示为现有真实农机绑定或真实轨迹**。
- 不向生产监测系统产生演示推送、通知、告警、控制指令、导出清单或审计事实记录；演示页面所需的本地 UI 交互不应触发真实业务动作。

### 5.3 地图表现

- 使用独立的 `demo` VectorSource/图层或清楚隔离的纯视图映射；演示多边形用区分于“正式已核实边界”的视觉样式（建议虚线、半透明/“演示”图例）。正式地图里已有的绿色实线/橙色虚线语义不能混淆。
- 演示模式允许全场适应范围、村庄点击范围定位、对象点击抽屉与缩放渐进显隐；没有模型坐标就不可伪装有真实位置。
- 保持显示地图底图的天地图服务；若底图瓦片失败，给出明确异常提示，保留演示目录。不要使用参考规划图代替天地图或当成底图测绘图层。

## 6. 新增/管理入口的完整交互路径

**建议的 UI**：左侧目录顶部（搜索之上或同排）放一个醒目的 `＋ 新增/管理` 菜单；桌面目录收起时地图工具栏仍能找到管理入口；手机目录中有同等入口。菜单至少包括 `新增村庄`、`新增地块/塘口`、`新增固定设施`、`登记机动设备`。只有获得相应权限且处于真实模式才能执行真实新增。

| 菜单项 | 真实模式用户路径（优先复用） | 不可伪完成的前置条件 |
|---|---|---|
| 新增村庄 | 打开当前 `RegionManagement` 的真实新增表单或对应受控业务入口；保存调用 `/api/v1/map-regions`，成功后目录立即刷新并可关联对象 | 当前用户有农场 `configure` 权；村庄只是分组，不是官方多边形 |
| 新增地块/塘口 | 导向 `/objects` 的正式对象维护表单，必要时加明显的选中类型/返回地图路径；复用 `/api/v1/objects`，创建后可走 `/map#boundary-draft` 正式边界草稿 | 需选农场、唯一编号、名称、来源，权限/版本/核验同原逻辑；不直接变成已核实边界 |
| 新增固定设施（如水闸） | 在 `/objects` 专业模块补能创建 `objects.kind=facility` 的薄 UI（原保存服务已支持该 kind），并按需要进入 `/devices` 登记其关联实体设备 | `facility` 对象和 `physical` 设备是两类身份，不能只画一个图标就生成可控制水闸 |
| 登记机动设备（无人机/农机） | 优先进入 `/devices` 的实体设备登记工作流，再在 `/machinery` 处理农机的机具/定位终端关系（适用时）；当前 `/devices` 若只有列表，需在**设备所属模块**补最小录入 UI，复用原 `saveDevice()` | `saveDevice` 必须指定已登记 `sourceId` 与关联对象，受对象配置权控制；无人机不是默认农机绑定，且登记≠核实≠定位≠执行权限 |

**不允许**：仅把按钮连接到一个只有列表、没有登记能力的页面却宣称“新增可用”；未经原业务前置检查偷偷创造“演示已核实终端”；在地图抽屉重复建设完整设备管理系统。若某条新增路径受已有资料/合同/数据来源限制，必须显示真实前置条件以及用户下一步去哪里补齐。

**权限规则**：无配置权限时不显示实写操作，直接访问 API 也必须被拒绝。演示模式始终只读，显示“当前是演示，退出后才能登记真实资料”与切换入口，而不是提交模拟对象。

## 7. 右侧抽屉的新信息层级

### 7.1 通用骨架（不同类型共享，仅内容不同）

```text
[ 类型图标 · 对象名称                     × ]
[ 所属区域/关联对象 · 关键状态 · 模式或可信度标识 ]

[ 2~4 个最重要的业务数字或事实 ]
[ 有意义的关注事项 / 当前任务（仅有数据时） ]

[ 查看完整业务 ] [ 编辑/管理资料（有权限；去原模块） ]

▸ 资料与记录（默认折叠：编号、版本、来源、登记时间、边界状态、权限说明）
```

核心规则：**先显示这个对象“现在对我有什么用”，后显示“数据库如何存它”。** 右侧的高度优先留给业务概要与下一步行动；系统元数据不是删除，而是默认折叠。首屏不应出现由五条元数据占据大半屏的情况。

### 7.2 六类模板

| 类型 | 首屏优先显示 | 次要信息、入口 |
|---|---|---|
| **农场** | 农场名称；授权可见的片区数、农田数、塘口数、固定设施数、机动设备数；有事实支持的待关注事项；“查看全部对象 / 管理区域” | 农场编号、版本、建档时间和资料来源折叠；计数严格服从授权，不把未知说成 0 |
| **村庄/片区** | 名称、片区的已关联农田/塘口/设施数量、关联关注事项、定位村庄、进入“管理关联” | 名称是经营分组，不自动声称行政村边界；没有关联边界则不能地图定位 |
| **农田** | 名称/所属片区、面积（有可信资料才有）、作物/生产阶段（来自原农事模块或演示）、关联设备、简短告警/任务摘要 | 跳 `/objects/{id}` 和原农事模块；元数据折叠 |
| **塘口** | 名称/所属片区、养殖品种（可信才显示）、2~3 项关键水质值与采样时间、告警、关联设备 | 跳原测点、水质、养殖记录/告警；离线或无数值须标“暂无可信监测数据” |
| **固定设施** | 名称/类型/位置来源、状态摘要与最后时间、关联对象、关注事项 | 跳原设备/维护/控制**申请**页面（有权限才出现）；抽屉不出现可直接控制的按钮 |
| **机动设备** | 名称/业务类型/登记归属、位置来源与时间、当前状态、最近作业概要（有依据才显示） | 跳原设备或农机/作业业务；管理归属≠当前坐标；无定位显示“位置未知” |

对真实模式，若业务系统尚没有作物、水质值、设备业务分类等可靠字段，显示“不提供/暂无可信数据”，不可因为模板要求齐全就扩表或伪造。对演示模式，则可用 fixture 把以上差异化模板全部展示出来。

### 7.4 视觉细则

- 沿用森林绿、浅米白、农业绿、水域蓝和有证据的警示橙；避免工业大屏式亮色与冗长元数据表格。
- 农场概要可采用两行紧凑统计；塘口、水闸优先状态或关键测值；在手机底部抽屉里首屏至少看到“名字 + 关键业务 + 操作入口”。
- 业务为空时只占一条“暂无可信数据”提示，不为每一个空字段显示整行“—”。
- 长“资料来源”文本默认不占用大版面，折叠后可换行显示，并允许查看来源路径（有权限时）。

## 8. 交互流程与实现边界

1. **首次真实模式**：打开总览；如果只有 `LZH-ROOT`，说明当前可用农业资料不足，提示“尚未登记村庄或地块，按新增/管理开始”，保留真实空状态，同时给出“查看演示效果”选项。
2. **进入演示**：切换后多片区与边界、演示关联和状态按同一份 fixture 出现；地图全场适应范围，点击片区定位，点击地块/塘口/水闸/机动设备展示差异化详情，支持返回全场与手机查看。
3. **离开演示**：明显退出入口；恢复真实模式读取与真实授权；不带回演示选中对象和搜索，不产生生产写入，也不把演示数据作为真实页面离线缓存。
4. **真实新增村庄**：菜单→村庄表单→提交已存在的区域管理 API→成功提示→目录立即出现，允许关联已有农业对象；无权限时不能展示可写操作。
5. **真实新增农田/塘口/固定设施**：菜单→原对象模块可用表单→受控写入→返回地图查看；无已核边界时目录能找到但地图不能伪定位。
6. **登记真实无人机/农机**：菜单→原设备管理界面，检查数据来源、对象归属、核实规则→适用时跳原农机绑定模块；不要求这轮创造一套实时轨迹页面。
7. **查看资料/业务**：地图的正式对象详情仍跳原对象、设备、农事、告警、农机等页面，并能返回之前的真实地图视角。

## 9. 工程与权限实现建议（允许 Codex 选择更简单方式）

- 建议把演示 fixture、模式适配和详情模板分成少量独立模块，避免继续将所有逻辑堆在 `src/app/(platform)/farm-overview/farm-overview.tsx` 单一组件。
- 可设置 `FarmOverviewData = { mode:'real'; ... } | { mode:'demo'; ... }` 等显式联合类型，由相同地图展示组件消费；演示 DTO 不能冒充原来服务端真实对象 UUID。
- 真实概要继续复用 `src/modules/map/overview.ts` 以及各专业模块，不在总览后端直接伪造监测值，也不让演示数据混入真实 `GET /api/v1/farm-overview`。
- 设备入口需审计 `/api/v1/devices` POST 的 `sourceId` 和 `objectId` 前置约束以及可用的来源登记界面。没有可管理的数据来源时必须解释阻塞原因；不得私建虚构来源或绕过审核。
- D3 原有网络错误提示、最后成功读取数据、桌面/手机布局、对象授权、专家可见性及 `sessionStorage` 返回状态都需回归；演示/真实模式的缓存键必须隔离。
- 优先避免数据库迁移、对业务表添加字段和改写权限模型；如确实必须，**先另行提交原因、迁移/回滚与最小方案供人工批准**。
- 新增水闸/无人机业务类型的视觉呈现可采用清楚的演示模板；真实设备分类若现有主档不支持，不能借 `devices.kind` 假装完成完整行业类型体系，先保留“未分类/待完善资料”的真实状态。

## 11. 交付与禁止事项

**交付**：代码改动、变更清单、设计前后对照截图、测试结果、明确未覆盖的真实数据验收、GitHub 提交；推荐在 `docs/acceptance/farm-overview-demo/` 记录本轮验证证据，沿用已有仓库命名规范。执行前先读 `AGENTS.md` 与最近提交，避免覆盖并行工作。

**严禁**：将虚构村庄/多边形/告警/设备数据写入生产库；修改真实设备核实逻辑使模拟设备“通过”；在演示模式下发送控制、绑定、工单、推送或告警 API；将用户图片当成法定行政村/地块边界；将原 `/map` 直接替换成新地图；以“演示模式看起来有数据”声称 T01—T15 现场验收全部通过；未经确认自动部署生产或做破坏性数据库变更。

## 12. 给验收人的一句话目标

> 用户打开真实农场地图时，能一眼知道如何新增村庄、地块、设施和农机；当现场数据暂不可用时，能主动进入明显标识的只读演示模式，看见完整的多村农业分布与**真正有用**的对象业务摘要；退出后仍然是干净的真实业务系统。
