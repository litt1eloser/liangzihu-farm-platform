## 1. 一句话产品定义

> **面向分散在多个村庄的农田、塘口和重要设施，建设一个以天地图卫星影像为主体、具备区域目录与对象概要的“空间化农场全景工作台”：打开先看全场分布，定位村庄后看农业对象，点击对象快速了解情况，再进入原有业务页面处理。**

**它不是**另一套设备监控中心、综合指挥大屏、数字孪生控制台，也不是替代原有业务模块的第二套数据库。

### 核心使用者和使用目标

- 有权限的农场管理人员：扫一眼掌握当前可查看的经营区域和少量关注事项；搜索、定位和进入业务处理。
- 有配置/编辑权限的人员：登记或维护村庄导航分组、地块/塘口和空间资料；保留来源、版本与授权要求。
- 普通查看用户或外部获授权人员：仅在**自己的授权范围内**浏览；不默认允许所有人看到整个农场。

**产品承诺**：地图解决“在哪里、是什么、有什么值得关注、下一步到哪个业务模块”，不负责亲自完成专业监测或设备控制。

## 2. 五项冻结决策（Q1—Q5 已全部关闭）

| ID | 最终决策 | 强制遵守的边界 |
|---|---|---|
| **Q1 区域组织** | **全场 → 动态村庄/经营片区 → 地块/塘口/固定设施**；机动设备为平级独立入口；另有“未归类/位置待登记”。授权用户能够新增、维护、归档村庄及农业对象。 | 村庄是导航分组，非必然的行政区、管理主体、权限单元；不能把列表写死在前端；不能用空间邻近推断对象归属。 |
| **Q2 地图展示** | **方案 B**：全场看区域分布和少量可信关注事项；放大到村庄再看地块/塘口及重要固定设施；选中后才看状态概要。 | 不在全场铺满设备名称和遥测值；原有正射、航次、注记等图层保留按需入口。 |
| **Q3 详情/编辑** | **方案 A**：右侧看概要；农业对象及真实设备的正式资料编辑、监测、农事、告警/工单等跳原有业务模块；仅普通地图注记可在地图编辑模式直接修改。 | 不重复开发专业业务表单、控制流程或同名台账；无事实就标明缺失/未知。 |
| **Q4 数据集成** | **方案 B**：继续使用正式对象/设备/测点/告警/工单等业务接口，在现有 Next.js 系统中补一层**轻量、只读、服务端授权的地图总览展示适配层**。 | 不创建平行的设备/农事/告警事实库，不让前端直接访问厂家接口；仅在必要时作兼容性数据扩展。 |
| **Q5 UI 定稿** | **John Deere 风格的清爽农业运营 UI**；复用平台导航；左侧区域目录可折叠，中央 OpenLayers + 天地图卫星影像占主体；**右侧详情选中对象后以抽屉覆盖地图边缘，默认关闭（方案 A）**。 | 不采用第三栏持续挤压地图的方案；打开抽屉不得使目标永久被遮挡，关闭不得重置地图视口。手机采用目录抽屉与底部详情，不生硬压缩桌面三栏。 |

**冻结结果**：以上五项是产品选择，不再通过日常讨论反复修改；遇到确凿实现障碍按第 10 节正式变更处理。

## 3. 农场导航与信息模型（产品语义）

```text
全部农场（表示当前账号已授权可见范围）
├── 区域目录
│   ├── [用户维护的村庄／经营片区 A]
│   │   ├── 地块
│   │   ├── 塘口
│   │   └── 固定设施
│   ├── [村庄／片区 B]
│   └── + 新增区域（仅授权配置用户）
├── 机动设备
│   ├── 农业无人机（有合法登记数据时）
│   └── 收割机／其他农机（有合法登记数据时）
└── 未归类／位置待登记
```

- **村庄/片区**：用户维护名称和关联对象；可在一期只登记几个村庄，二期再加入其他村庄，**无须改代码**。它不自动代表官方行政边界。归档应保留历史和已有业务关联。
- **正式农业对象**：农田（`field`）、塘口（`pond`）、渠道（`channel`）、设施（`facility`）、农场（`farm`）等沿用正式 `objects` 身份、版本与权限。可由授权用户新增、编辑基本主档和登记边界；草稿与核实后的边界严格区分。
- **固定设施**：登记归属/关联对象和可信登记位置；在区域尺度渐进显示，专业数据仍归设备模块管理。
- **机动设备**：**管理归属或停放基地 ≠ 最新位置 ≠ 具有实时有效性的当前位置**。跨村作业不改变登记归属；无实时位置源时仅显示注明时间/来源的登记位置或最后已知位置，或显示“位置未知”。此版本不做轨迹历史平台。
- **私人地图注记**：与正式农业对象、设备、航次疑点注记分别建模和标识；私人草稿**不会因为点击或换了图标就升级为真实设备**。
- **缺失数据**：无可靠位置/边界的地块仍可在目录中找到，但不生成假定位；无官方村庄边界时，不绘制所谓“行政村范围”。

这些是**用户看到的导航和业务概念**，不是强制规定 SQL 外键层级。具体村庄分组存储方式留待实施审计确定。

## 4. UI 设计规范（交给原型设计与前端的产品约束）

### 4.1 桌面布局

```text
┌────────────── 沿用原平台的导航与身份/权限 ───────────────────────────┐
│ 农场全景 | 当前区域路径 | 全场视图 | 图层 | 编辑地图 | 三维入口(沿用)  │
├────────────────┬──────────────────────────────────────────────┤
│ 左侧区域目录   │ 中央：天地图卫星影像 + OpenLayers               │
│ · 搜索         │ · 全场：区域分布、少量关注提示                   │
│ · 全部农场     │ · 村庄：农业对象边界、必要的设施                 │
│ · 村庄分组     │ · 选中：高亮、与目录同步                         │
│ · 机动设备     │ ┌───────────────────────────┐                  │
│ · 位置待登记   │ │ 右侧详情抽屉（默认关闭）   │ ← 选中才展开     │
│ (可折叠)       │ │ 概要 / 证据 / 业务入口     │                  │
│                │ └───────────────────────────┘                  │
└────────────────┴──────────────────────────────────────────────┘
```

- **右侧抽屉覆盖地图的右边缘，不改成永久第三栏**；展开不应导致地图中心、缩放级别被无端重置。若对象位于抽屉遮挡范围，提供适当的地图偏移定位；关闭后尽量保留当前视口。
- 左侧目录支持折叠；目录负责“到哪里”，图层面板负责“显示哪些图层”，搜索/筛选不能扩大可见权限。
- 默认画面：突出卫星影像而不是统计卡片；紧凑的顶部操作，不建设监控大屏式的多屏布局。
- 色彩只固定原则：暖白/深绿为底，农田柔和农业绿、塘口水域蓝、真正需要关注的事项使用有限的提示色；未核实/草稿要有线型或文字区分。**不只靠颜色表达状态**。像素、色值、动画节奏在视觉原型阶段定，不再作为新产品需求。

### 4.2 缩放与内容渐进

| 地图观察层级 | 默认显示 | 不默认显示 |
|---|---|---|
| **全场** | 已授权的村庄/经营区域分布、地块/塘口有来源的汇总、少量确实存在的关注事项 | 普通传感器全量图标、每台设备实时数据、全部地块名称 |
| **村庄/片区** | 具体地块/塘口边界与名称、渠道及重要固定设施 | 所有摄像头和普通测点同时铺开 |
| **对象附近** | 选中对象、周边必要设施、关联对象入口 | 专业监测页中的全部图表/表单 |

缩放阈值、标记避让与聚合算法由技术设计确定，以实际屏幕和真实样本验证；**不因自动聚合丢失异常提示或数据来源说明**。

### 4.3 右侧概要统一骨架

| 对象 | 第一屏推荐摘要（仅在现有真实可信数据可获取时显示） | 进入原业务模块的入口 |
|---|---|---|
| 农田 | 名称、村庄/归属、边界状态、作物或生产批次、关注事项 | 对象详情、农事/生产、关联设备、工单 |
| 塘口 | 名称、村庄/归属、边界状态、养殖信息、少量水质摘要与告警提示 | 对象详情、水质测点历史、养殖记录、告警/工单 |
| 固定设施 | 名称、类型、归属、经核实位置、可用的简要状态、数据更新时间 | 原设备台账、测点详情、维护、已有控制申请入口（若获授权且原模块可用） |
| 机动设备 | 名称、管理归属、定位类型、位置来源与时间、可用状态摘要 | 原设备/飞行/作业业务页面 |
| 普通注记 | 标题、备注、创建/修改信息、注记类型 | 仅在地图编辑模式编辑注记资料 |

- **缺少字段时显示“暂无资料／未核实／位置未知／数据过期”等明确事实**，不填入演示数值、不自动显示“正常”。
- “设备在线”“数据新鲜”“测量质量有效”“设备无告警”是不同含义，不合并成一个臆造的绿色状态。
- 业务入口只有当真实页面/授权范围存在时才显示可用操作；不做空壳按钮。**地图本身不发厂家控制命令。**

### 4.4 手机适配

- 沿用原平台登录与权限；二维地图优先。
- 地区/设备目录通过可收起的抽屉访问；对象概要采用底部面板，至少可以展开/关闭，不遮蔽全部地图操作。
- 手机端本轮验收的是**基本浏览、搜索、定位、概要与原业务入口**；原项目另有的离线填报/照片草稿不在地图模块重建，但不能受本轮改动破坏。
- 分辨率和断点通过原型测试确定，不作为隐藏新增功能的理由。

### 4.5 最短完整交互链

```text
登录 → 进入农场地图 → 看到有权查看的全场分布
  → 左侧搜索/选择村庄 → 地图定位到该村关联的地块/塘口
  → 点击对象 → 右侧抽屉显示基本信息、来源和业务入口
  → 进入原有监测/农事/告警/台账页面 → 返回地图
  → 保持或恢复此前区域、选中对象、地图视口与必要的筛选
```

编辑链：授权用户新增一个村庄 → 登记地块/塘口及所属导航分组 → 根据已有核验机制保存边界草稿 → 列表和地图正确呈现；无权限用户不能通过按钮、接口或直链实现修改。

## 5. 最终开发范围：本轮必须交付 / 直接继承 / 明确不做

> 这里的“本轮”是**空间化农场总览工作台的开发增量**。导师原项目已安排的其他一期/二期功能，仍属其自身计划，**不等于被取消，也不等于全归本轮团队负责**。

### 5.1 本轮 P0：需要落实并验收的功能

| ID | 交付范围 | 完成定义（不规定实现细节） |

| **S05** | 渐进式可见信息与图层入口 | 全场少量分布/关注事项，放大显地块/塘口和重要设施；原有航次/正射/注记等可按已有方式访问或叠加，不要求本轮重写其专业界面。 |

| **S07** | 机动设备独立列表 | 复用已有设备身份；能区分归属、登记/最后位置与真实有效当前位置，不存在实时来源时不标“实时”。不新增轨迹采集系统。 |
| **S08** | 服务端轻量只读总览适配 | 按现有授权获取地图必需的区域/空间/概要/关注数据；不重复建设监控数据源或业务事实表。 |

| **S10** | 桌面/手机基本可用及旧模块回归 | 完成第 8 节验收矩阵；账号与对象范围权限、草稿/核实/模拟来源都不因新 UI 被绕过。 |

**产品范围内，但尚须技术审计决定方案的最小补充**：动态村庄分组数据结构及操作接口、正式对象与区域的关联、业务设备类型的地图表现方式、只读聚合查询、可靠返回地图状态、对象边界草稿的 UI 封装。它们不是“全新平台”，但不能错误承诺零数据库变更。

### 5.2 原项目必须继承和保护：不是本轮重写任务

| 原有系统/资产 | 当前已知基础或约束 | 本轮必须怎样对待 |
|---|---|---|
| `objects` + `object_versions` + `boundary_versions` | 正式农业对象、边界可信状态、来源、版本、权限 | 原有业务 ID 不变；草稿/已核实不混淆；保留审计与并发保护。 |
| `devices` + `data_sources` + `points` + `point_bindings` | 真实设备、数据来源、测点和对象关联 | 只引用主档，不复制业务设备；`devices.kind` 为技术类别而非农业业务设备类别。 |
| `device_positions` | 设备位置按来源、核实与版本保存 | 不能视为实时 GPS 历史流；地图展示位置事实要带来源与时间。 |
| `observations` + `point_current` + `source_health` | 监测测值、采样时间、质量和接入健康 | 地图做有依据的摘要；不把接入云端成功当设备现场在线。 |
| 原告警/维护/工单/控制申请 | 专业处置与分层授权链 | 展示关联摘要并跳转；不得在地图另建平行处置流程或发送控制指令。 |
| 原农事、养殖、生产批次、影像、库存、溯源、科研等 | 导师既定业务范围，部分能力依赖现场数据或团队集成 | 保留体系与原始权限；暂不假定所有页面、数据均已接通。 |
| 正式 `/map`、`GET /api/v1/map` | 对象边界、位置、航次覆盖、正射预览、疑点注记等正式空间资料 | 不直接删除或以漂亮新页取代；逐步兼容与回归。 |
| `/map-prototype` + `satellite_draft_points` | 天地图卫星原型与私有点位草稿 CRUD | 中文输入、持久化、所有者隔离、版本冲突行为保留；不擅自迁移成正式对象。 |
| `/terrain`、Cesium/三维、测绘资料核验 | 原项目的二维/三维独立阶段及验收要求 | 既有入口继续可用；本轮不重写三维，不取消后续地形灌排验证。 |
| 原平台身份、安全、日志、多端与离线填报 | 角色 + 对象范围授权、专家资源级授权、审计、企业微信/手机等 | 服务端实际校验；不能因为地图汇总、聚合或导航泄露未经授权的位置、数量、附件。 |

### 5.3 明确排除本轮新增的功能（拒绝范围膨胀）

- **第二个设备实时监控中心**、专业监测图表、重新开发告警引擎/工单/农事/库存/养殖管理。
- 直接下发水闸、水泵、无人机等**实际执行指令**，或实现新的设备控制协议/适配器；真实控制仍按原有独立审批及现场验证推进。
- 专业 GIS 编辑器全套能力、复杂拓扑修复、通用自定义属性建模器、可编程设备插件/协议市场、任意设备类型设计器。
- 连续 GPS 轨迹平台、轨迹历史回放、跨村自动调度、无人机自动飞行任务编排、实时地理围栏推断。
- 新建三维 GIS/数字孪生编辑器、3D—2D 全对象实时联动、三维地形水力结论；导师原规划的三维阶段仍然保留。
- 全功能自定义地图专题、复杂 BI 大屏、运营健康度打分、凭空生成的实测数据、自动认定真实村庄行政边界。
- 将“画任意线/面、测距测面、图标市场、历史动画”等地图标注扩展**自动变成本轮 P0**。已在其他既定计划中的内容保留其原计划，不因本文被取消；确需加入当前增量必须经变更评审。

**重要区分**：“不在本轮新增”不等于“删除已有功能”，更不意味着导师原有整个平台不再做这些模块。

## 6. 后端与数据集成原则：产品定边界，技术保留实现自由

### 6.1 已审阅的真实接口/数据库事实（当前开发仓库）

| 位置 | 当前可确认的作用 | 本轮差距 |
|---|---|---|
| `GET /api/v1/map`、`src/modules/map/service.ts` | 按权限获取对象边界、设备点位、航次覆盖、栅格预览、航次注记；可带 bbox | 并非直接可用的跨业务全景聚合接口；无几何对象不能只靠 bbox 取回。 |
| `GET/POST /api/v1/objects`、`src/modules/registry/objects.ts` | 对象主档读取、创建、改名，关联父对象；类型当前限定 farm/pond/field/channel/facility | 不含 village；区域导航需独立兼容方案；对象“归档/归类/边界编辑”具体可用操作需审计，不能假设已有完整界面。 |
| `devices`、`device_positions`、设备接口 | 设备身份、关联对象和版本化经核实位置 | `devices.kind` 技术类别不等于水泵/无人机/收割机的地图图标类别，缺完整实时移动位置契约。 |
| `points`、`point_current`、`src/modules/telemetry/queries.ts` | 测点/历史、当前值、质量、新鲜度和数据来源语义 | 地图摘要需安全且高效地映射；不可由一个测点代替整台设备状态。 |
| `/api/v1/alerts`、`/api/v1/work-orders` | 原有业务事件与工单 | 地图关注事项只能有权限地关联汇总，不能新增平行事实表。 |
| `/map` 与 `/map-prototype` | 正式地图与卫星 OpenLayers 原型并存 | 要制定集成/路由回退及回归策略，避免覆盖后才发现旧功能丢失。 |

### 6.2 允许新增的最小类型

- **区域目录存储与必要的区域对象关联**：实现用户动态新增/维护/归档村庄；可无几何；不得冒充官方行政边界，也不得把区域当成默认授权单元。
- **少量设备业务展示类型映射**：满足已有设备类型图标与目录分类；必须保持设备身份和厂家接入方式不变。
- **只读地图总览 API/呈现适配器**：负责按用户对象及资源范围裁剪数据，组织小型概要、分布和关注事项。要能分别表达“无数据、无权限、未知、未核实、过期、模拟”，而不是一种空值表示全部情况。
- **必要的原有对象入口 UI 适配**：让授权人员能够完成已冻结的动态区域、农业对象和草稿边界基本管理；写操作必须走原主档/已有审计与权限链。

**禁止**：重建平行业务库、把用户草稿点转换为设备登记记录、客户端直连数据库/厂家、凭空间距离关联水路/设备归属、未经现场证据将设备标成在线或可遥控。

### 6.3 特别保留的技术决策自由

本版**不预先指定**：村庄分组究竟建表还是通过兼容分类实现、聚合 API 的具体路径与响应 JSON、哪种全局状态缓存/查询库、缩放阈值、图标聚合策略、前端状态保存方式、精确侧栏宽度。Codex 先做代码审计和可行方案，再单独提案审阅，避免“产品文档替代码编造接口”。

## 7. 数据可信、权限与原有安全约束（不可退让）

1. **服务端授权**：地图、搜索、聚合统计、关联预览、附件、跳转和修改全部沿原权限；专家资源级限制依旧有效。前端隐藏不等于获授权。
2. **空间数据来源**：边界/位置记录来源、坐标、版本与核实状态；缺少位置时展示“待登记”，不能自造地图坐标；没有村庄行政边界就不画假边界。
3. **状态多维**：数据来源、采样时间、更新时效、观测质量、连接健康、告警状态独立，不能偷换概念。
4. **演示隔离**：模拟对象/模拟数据从接口到 UI 明确标记；模拟状态不参与真实农场统计或实际控制反馈。
5. **移动资产**：管理归属不随定位变化；最后位置不是实时位置；无有效数据时明确说未知。
6. **真实设备控制边界**：原项目的控制申请、授权与结果反馈链条优先，地图不新建实际下发能力；真实执行适配器未联合签验不得显示已执行成功。
7. **已有功能不倒退**：地图 UI 迭代不可破坏原二维/三维、航次、测点、点位草稿、审计、原对象版本和企业微信/手机功能。

## 8. 可执行的最小验收矩阵（产品定义，不代替测试用例）

| 编号 | 场景 | 必须可观察的结果 |
|---|---|---|
| **T01** | 登录后进入全场视图（有多个不连续村庄） | 真实天地图影像、已授权区域、正确全场视口；无权区域及其摘要不泄露。 |
| **T02** | 选择村庄 A，再搜索村庄 B | 目录/地图定位同步、视口正确；村庄没有官方边界也能按合法关联对象定位。 |
| **T03** | 已授权用户新增/改名/归档村庄，二期新增新村 | 无代码修改即可生效；已有对象关联及历史记录不被误删。 |
| **T04** | 已授权用户新增农田/塘口，保存边界草稿 | 返回正式对象 ID 和草稿状态；对象出现于正确导航，未核实边界不伪装权威；无位置仍可从列表访问。 |
| **T05** | 全场→村庄→具体对象 | 全场无密密麻麻设备图标；放大后按需显设施；点击高亮与列表选中一致。 |
| **T06** | 点击塘口及设施 | 右侧**覆盖式抽屉**出现、信息有来源/时间、缺数明示，关闭不复位；被抽屉遮挡的目标能重新露出。 |
| **T07** | 从塘口进入水质/农事/告警等业务页再返回 | 入口确实存在且获授权；保留/恢复前次地图视口、对象与必要筛选；不复制监测逻辑。 |
| **T08** | 浏览机动设备并模拟跨村移动 | 目录不改变管理归属；当前位置由可信来源驱动；没有实时来源时不能展示“实时在线位置”。 |
| **T09** | 无坐标、无村庄归属、无遥测、过期/异常/模拟数据 | 目录和概要正确标记，各种未知不被替换为默认“正常”；模拟显著可见。 |
| **T10** | 不同角色、已失效专家授权、直连 API | 返回内容、汇总数量、图片和写入均受原有服务端权限限制；未授权操作失败。 |
| **T11** | 切换已有图层或查看历史航次/正射资料 | 原空间资料与入口依然可用；切换显示不改变真实几何、身份或授权。 |
| **T12** | 使用已有地图私人点位 CRUD（中文输入、更新、删除、冲突） | 原数据隔离、持久化与版本行为不退化；普通注记不生成真实设备。 |
| **T13** | 正式 `/map`、`/terrain`、对象/设备/告警/工单页面回归 | 原路由与关键功能保持可用；任何迁移需先有回滚/回归证据。 |
| **T14** | 桌面常见屏宽与手机窄屏 | 左侧可收起、桌面右侧覆盖式抽屉、手机列表抽屉和底部概要能实际操作；键盘与基本焦点顺序可访问。 |
| **T15** | 断网或厂家接口故障 | 已加载资料如何保留、失败/过期如何提示均可理解；不能把来源恢复直接标成设备完全正常。 |

验收数据采用**获得许可的真实测试对象**，或明确标记为模拟的完整测试样本。不能把虚构的村庄/地块数量、效果图或漂亮截屏当作现场真实验收。

## 9. 建议开发顺序：只排依赖，不临时加功能

本章是**可供实施设计参考的阶段划分**，不意味着已下达编码任务。每阶段结束应保留可运行的已有系统。

| 阶段 | 先做什么 | 进入下一阶段的门槛 |
|---|---|---|
| **D0 只读审计** | 对照当前 `objects`、`devices`、`map`、`map-prototype`、遥测、告警、权限、原路由和已运行环境，列出可复用/缺口/拟增 API 与迁移 | 给出数据库兼容、角色与资源级授权、已有页面保护及回滚清单；批准前不得动代码。 |
| **D1 UI 空壳与全场导航** | 复用卫星 OpenLayers、平台导航和真实授权空间数据；先实现左侧目录、地图全场/搜索定位、抽屉选中骨架 | 在多个离散授权区域完成 T01、T02、T05、T06 的无副作用流程。 |
| **D2 最小数据补充** | 动态区域分组、正式对象可维护入口、只读聚合概要与状态证据、机动设备分类 | T03、T04、T07—T10 通过；没有新平行业务事实。 |
| **D3 衔接与回归验收** | 旧地图能力兼容、普通标注保护、手机适配、关注事项/图层入口和完整回归 | T01—T15 全量验收，问题关闭后才考虑逐步替换入口。 |

每一阶段的具体工作量、是否需要 SQL 迁移、地图组件如何重构，待 D0 审计后安排；**不得为了赶进度直接覆盖 `/map` 或原业务 API**。

## 10. 后续需求变更控制（防止无限加需求）

- v1.0 从 2026-10-09 起作为本轮产品范围基线；**五项 Q1—Q5 均关闭**。
- 新想法默认记入“候选池”而**不进入开发清单**。只有当它修复安全/数据正确性问题、解决 P0 真实流程的阻断，或原项目已明确列为此阶段的必要约束时，才进入变更评审。
- 变更申请必须写：**决策 ID / 原结论 / 新提议 / 必要原因与证据 / 对现有模块与权限影响 / 增加的开发及回归成本 / 是否有替代方案 / 批准人 / 生效版本**。
- 设计稿提出新图表、新专题、新移动调度、新交互动画时，默认先判断能否用现有能力完成，而不是加入 P0。
- 实施中发现原系统根本不存在某个设想中的业务页面时，**先在 UI 显示入口不可用或明确缺口并汇报**，不允许私自补建一整套专业业务。
- **P0 的“完成”以第 8 节验收场景达标为准，不以功能数量或界面酷炫程度为准**。验收通过之后，再讨论 v1.1 的候选需求。

## 11. 仍待核实的外部事实与技术问题（不是重新打开产品决策）

| 问题 | 当前已知 | 处理人/时机 |
|---|---|---|
| 经营主体是否唯一？ | 当前只是假设“单一农场统一经营”；多个村庄分散经营已确定 | 向项目负责人核实；不因此改变本版导航规则。 |
| 村庄名称、可靠中心点、实际对象名单/范围 | 尚需现场或业务登记核实；行政边界未获验证 | 数据整理与现场团队提供可信样本；设计允许缺坐标。 |
| 机动设备是否已有实时位置 API | 原 `device_positions` 不能证明有实时 GPS；机型和来源需核实 | 与负责设备/无人机的团队核对；无源即显示未知/登记位置。 |
| 水质、养殖、作业、告警页面是否具备所需可用数据与入口 | 已有部分测点、告警和工单接口；不等于所有养殖信息都有独立页面 | 技术审计按实际路由梳理，并形成“现有/待接入/不可用”目录。 |
| 动态区域分组与正式对象增改归档如何实现 | `objects.kind` 不包含 `village`，已有对象 API 不能直接视为完整区域后台 | D0 只读审计提出最小兼容设计，另审后实施。 |
| 天地图 Key、网络、容量和现场坐标精度 | 原型报告仅验证一组开发环境下瓦片请求与交互 | 上线前按环境复测，不把原型运行成功等同正式上线验收。 |

## 12. 版本冻结结论与交付交接

**v1.0 产品结论**：

> 用 John Deere 式的清爽农业 UI，在**左侧动态区域目录 + 中央真实卫星地图**中浏览分散村庄的农业经营对象；默认全场简洁、放大看设施；点击对象时从右侧以**覆盖式抽屉**呈现简要而可信的资料，并通过原模块处理专业业务。地图新增的后台只限必要的区域分组与服务端展示适配；保留原项目的对象、设备、权限、告警、航次、二维/三维和私人点位能力，不重做业务、不接管设备真实控制。

**交给 Codex 的下一份工作应当是“只读代码审计 + 实施方案”**，先列出真实可复用项、缺口、最小数据库/API 变更、原功能保护策略、按 D0—D3 排序的任务和测试计划；提交审阅之后才开始编码。
