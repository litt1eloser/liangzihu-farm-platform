# 摄像头按田块共享接口（第一阶段）

农田、设施等子系统已有农业对象 ID 时，可调用 `GET /api/v1/cameras/by-object?objectId=<对象 UUID>`。请求使用平台现有登录会话；接口只读，不抓拍、不唤醒设备、不打开直播。

返回 `object` 与 `channels`。每个通道包含设备 ID、名称、父设备名称、接入平台、已核通道号、最近有权查看的事件，以及两类图片：`eventImage` 为最近可访问的事件关联图，`captureImage` 为最近可访问的平台抓拍图。图片字段含 `url`、`capturedAt` 与 `referenceAt`：`capturedAt` 为空表示拍摄时间未知；事件图的 `referenceAt` 是事件时间，抓拍图的是保存完成时间，二者不能冒充拍摄时间。图片通过已有 `/api/v1/media/<assetId>` 接口再次鉴权读取。

农田或设施前端可以直接嵌入 `src/components/platform/camera-object-summary.tsx` 的 `CameraObjectSummary`，传入已有 `objectId`。如需自定义界面，可直接使用上述 JSON 接口。设备列表仅包含与该对象有已核实关系的通道；没有记录时返回空数组，不造模拟数据。当前模型按一个通道对应一个对象查询，跨多个田块的覆盖关系尚未建模。

```tsx
import CameraObjectSummary from '@/components/platform/camera-object-summary';

<CameraObjectSummary objectId={field.id} />
```

## 新块 12 试点

新块 12 的物理设备与两个通道已在本机数据库登记，并已在 `/imagery` 分别试播。其他人的数据库不会因拉取代码而自动获得这些登记；应按实际归属和资料在各自环境核实。抓拍或事件图片尚未因此自动进入新仓库。Token、设备验证码及真实图片原件留在私有台账或安全配置中，不提交到 Git 仓库。

## 管理员直播入口

农田、设施等页面需要按对象打开直播时，可嵌入 `src/components/platform/camera-object-live.tsx`。页面只传入已有农业对象 UUID，组件查询已核实通道，显示每路的「打开直播」按钮；管理员主动点击后，经现有 `/api/v1/cameras/reads` 申请直播并等待后台准备，再由现有播放链显示画面。关闭组件或点击「停止播放」会断开本页播放器；组件也在两分钟后停止本页播放。重新打开会产生新的读取请求。

```tsx
import CameraObjectLive from '@/components/platform/camera-object-live';

<CameraObjectLive objectId={field.id} />
```

使用方可以决定组件所在位置和周边页面布局。两个通道分别显示，不将新块 12 的设备 ID 写入农田页面。接口仍以登录身份、对象与设备授权、已核能力以及环境中的试点通道名单检查请求。当前加密直播仅管理员可用，且依赖 `CAMERA_READS_ENABLED=1`、`CAMERA_EZOPEN_BROWSER_ENABLED=1`、试点设备 ID 配置、摄像头 worker 与本地播放器资源。浏览器在管理员试播链中会接触萤石播放 Token 与设备验证码，因此不要把此入口开放给普通用户；普通用户播放需另设计授权和凭据保护。现有 `GET /api/v1/cameras/by-object` 仍是只读查询，不会自动启动直播。

本次只提供可嵌入入口，未改动农田页面布局；新块 12 两路直播此前已在本机 `/imagery` 试播，跨页面入口尚需管理员在目标页面实际打开两路确认。是否能在现场返回图片，取决于对应设备登记和真实媒体入库情况。
