# 新块 12 双通道加密直播试点

本分支复用旧仓库 2026-10-14 在通道 1 曾播放成功的萤石 EZOPEN + EZUIKit 链路，供同一台新块 12 设备的通道 1、通道 2 分别使用。通道 2 尚无真实播放验证记录，旧仓库的通道 1 成功记录也不能代替本仓库的设备登记和现场验收。当前只开放**主动点击的直播**；抓拍、回放、事件图片不在本次范围。

## 启用前的登记

1. 在当前数据库核实农业对象、萤石来源、这台物理设备及两个通道子设备，并记下**两个通道子设备 UUID**。不要复制旧数据库的对象 UUID，也不要为了展示把道路摄像头挂到错误田块。
2. 分别登记通道 1 和通道 2 的实际型号、固件、接口依据、凭据引用名、通道号和各自的能力依据；确认后只标记 `live=true`、`encrypted=true`、`readOnlyConfirmed=true`，保持 `playback=false`、`capture=false`。在私有表单登记各通道所需的设备验证码，数据库只保存加密值。
3. 部署环境私下配置 `IDENTITY_ENCRYPTION_KEY`、已核萤石 Token 引用、`CAMERA_READS_ENABLED=1`、`CAMERA_EZOPEN_PILOT_DEVICE_IDS=<通道1 UUID>,<通道2 UUID>`，经管理方确认试点权限后再设置 `CAMERA_EZOPEN_BROWSER_ENABLED=1`。不要把 Token、验证码或 `.env.local` 提交到 Git。
4. 应用部署时先执行新增的 `048_ezuikit_encrypted_streams.sql` 迁移，并安装锁文件依赖。启动应用和摄像头 worker 后，管理员到 `/imagery` 分别主动申请两路直播，再点击“打开本人临时播放”。

## 当前边界

- EZUIKit Web 播放器按萤石官方接口需要 `accessToken` 和包含验证码的 EZOPEN 地址。试点接口因此**仅管理员可请求、默认关闭、只允许显式配置的两个通道 UUID**；每次播放两分钟后自动停止。管理浏览器仍会接触这些凭据，生产扩展到其他角色或 106 路前必须另行确认设备级授权或安全播放方案。
- 页面加载、列表刷新和切换通道都不唤醒摄像头。只有用户主动请求且能力、权限、配额通过后才触发读取。
- 本次没有把旧仓库的视频墙、自动抓拍或回放能力带入。新仓库尚未提供真实登记记录与真机联调结果，不应把“代码已合入”写成“已播出”。
