# D2 数据模型与业务整合验收记录

日期：2026-10-09。范围依据[冻结产品定义](../../../计划/产品定义与最终开发边界%20v1.0.md)、[D0 审阅](../../../报告/空间化农场总览-D0只读审计与实施方案.md)和[D2 迁移回滚方案](../../plans/2026-10-09-D2迁移顺序与回滚方案.md)。

## 已交付

- `map_regions` 与 `map_region_links` 支持农场内村庄新增、修改、归档、恢复和对象关联。一个对象只有一条当前关联，旧关联保存起止时间、操作者及依据。新总览只按授权对象计数；专家不进入村庄聚合接口。
- 地块与塘口在对象台账可创建、更名、归档、恢复并进入原地图边界草稿表单。正式主档增加可空归档状态；对象版本、农事记录、测点、设备及历史资料保留。新总览默认隐藏归档项，原对象台账显示归档状态，原 `/map` 读取保持原行为。
- `/farm-overview` 按已授权村庄展示对象、只读的未关闭告警/农事记录/测点数量，依据有效 `machinery_bindings` 展示机具与终端并链接 `/machinery`。未确认机动身份的设备不自动列入机动目录；历史轨迹不标为实时位置。
- 原 `/map`、`/map-prototype`、`/terrain` 与闸门控制准备页面保持独立。

## 迁移与回滚实测

部署前发现运行库已有闸门迁移 `045_gate_deployments.sql`，因此 D2 使用 `046_map_regions.sql`、`047_object_archive.sql`。保留闸门的 Git 提交并与 D2 合并，未改已应用的 045 文件。

生产库 `agri_dev` 在 D2 前已备份为私有 `.local/backups/d2-2026-10-09-pre.dump`；通过 `pg_restore -l` 核对，并恢复到临时数据库检查迁移版本，再删除临时库。随后分别执行 046、047，迁移表显示 045、046、047 顺序正确。旧 Web 构建保存在私有 `.local/previous-next-d2-2026-10-09`；发现新页面问题时可先切回旧构建，保留新增表与列。备份后的正式业务写入不可被无评估地覆盖。

## 实际验证

- 独立 `agri_test` 随机 schema：区域跨农场拒绝、关联历史、归档恢复；正式对象版本与旧列表兼容；授权总览和有效农机绑定；管理员、经营主体、技术员、作业人员、维保人员及专家角色的配置权检查。合并后相关集成用例 7 项通过。
- TypeScript 检查和 Next.js webpack 生产构建通过。独立测试库浏览器检查覆盖 D1 地图选中与目录折叠、D2 村庄目录/概要/权限/旧页面、闸门准备页面；均通过。
- `luminous` Web 切换后健康接口返回 200，登录页返回 200，新总览未登录返回 401。生产库只保留现有真实记录，未写入截图中的合成对象、村庄或机具。
