## 二、组件行为（读代码核实）

`CameraObjectLive({objectId})`:
- 用 `GET /api/v1/cameras/by-object` 列通道（只读，不唤醒设备）;
- 点「打开直播」→ `POST /api/v1/cameras/reads`(operation=live，每次新 requestKey)→ 2 秒轮询到 ready → 按 `streamKind` 选 `EzopenSessionPlayer` 或 `CameraPlayer`;
- 两分钟到点 `setStopped(true)` 卸载播放器（卸载触发播放器清理）;
- 「停止播放」按钮、切换 objectId 时重置全部状态；
- `actualReadsEnabled=false` 时禁用按钮并提示。

权限与安全仍由服务端既有门控承担（管理员+白名单+开关+验证码），组件本身不接触凭据——这一点与本分支一致。

## 三、与 `feat/gis-camera-integration` 的重叠与差异

| 维度 | 本提交（camera-object-live) | GIS 分支（camera-section + camera-live-modal) |
|---|---|---|
| 形态 | 页面内联区块 | 任务书要求的模态弹窗（背景保持地图） |
| 通道信息 | 仅名称 | 名称/父设备/平台/通道号/已保存图片/事件 |
| 状态文案 | 直接展示 `error_code` 原文（如 CAMERA_PILOT_SCOPE) | 中文诚实映射（camera-read-error.ts，有单测） |
| 准备状态 | 「正在准备直播画面…」 | 申请中/设备唤醒中/失败分态 |
| 两分钟限制 | 有（卸载播放器） | 有（EZUIKit 内置 + 弹窗提示） |
| 空态/无权限/失败分态 | 有（较简） | 有（按 V1.2 空态口径） |
| 演示模式隔离 | 未处理（由使用方决定） | 演示对象不请求接口 |

**结论建议**：两者解决同一需求，**合并前只保留一套**。GIS 任务书指定弹窗形态与 V1.2 空态口径，建议以 GIS 分支实现为主；她这份组件可作为其他页面（非地图）内联直播的候选，但其 `error_code` 原文直出建议改用语义化文案（可直接复用 `camera-read-error.ts`)。合并决策超出本审阅范围，需双方确认。
